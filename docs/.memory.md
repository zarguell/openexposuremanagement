## Milestone 2: Database Schema & Migrations ✅

### Migrations Created (7 sets)

1. **000001_create_tenants_table**
   - Core tenant management
   - Auto-update timestamps via trigger

2. **000002_create_rbac_tables**
   - Users, roles, user_roles (many-to-many)
   - API keys with scopes, bound_source, and revocation support
   - MVP roles: admin, analyst, viewer (to be seeded)

3. **000003_create_asset_tables**
   - Assets with canonical_name and time windows
   - Asset identifiers with support for multiple types
   - Indexed for matching algorithm: `external_id:*`, `hostname_norm`, `shortname_norm`, `ipv4`

4. **000004_create_findings_tables**
   - Finding definitions (scanner-agnostic)
   - Finding definition aliases (CVE support)
   - Finding instances (per-asset observations)
   - Effective status computation fields: `effective_status`, `effective_reason`, `effective_revision`

5. **000005_create_suppression_tables**
   - Suppressions with workflow states
   - Suppression reviews for audit trail
   - Tenant policy state with revision counter for recompute trigger

6. **000006_create_threat_intel_tables**
   - Global intel_cve table (EPSS, KEV data)
   - Intel sync runs tracking

7. **000007_create_dashboard_views**
   - Materialized views for dashboard counts
   - Unique indexes for `REFRESH CONCURRENTLY` support
   - Views: counts by status, asset summary, open findings summary

### Key Schema Decisions
- All tables are tenant-scoped (except intel_cve which is global)
- Used BIGSERIAL for primary keys to support large scale
- JSONB for flexible metadata (scopes, evidence, references)
- Check constraints for state machines (suppressions, sync runs)
- Composite indexes for common query patterns (tenant_id + filters)
- Partial indexes where appropriate (active assets, KEV flags)

### Validation
- ✅ All migrations have up/down files
- ✅ Total of 14 migration files (7 up + 7 down)
- ✅ Naming convention: `{version}_{description}.{direction}.sql`
- ✅ Ready for `make migrate-up` and `make migrate-down`
